R2E — Rust Enterprise Edition

CLI Scaffolding

The r2e CLI generates project scaffolds and code templates, saving you from writing boilerplate.

Creating a new project

r2e new my-app

In interactive mode (the default when no flags are provided), you’ll be prompted to choose:

  • Database: None, SQLite, PostgreSQL, or MySQL
  • Features: Authentication, OpenAPI, Task Scheduling, Event Bus, gRPC Server

Or use flags directly:

# Full-featured project with SQLite
r2e new my-app --full

# PostgreSQL with auth and OpenAPI
r2e new my-app --db postgres --auth --openapi

# gRPC server with scheduler
r2e new my-app --grpc

# Minimal project, no interactive prompts
r2e new my-app --no-interactive

Generated structure

A minimal project:

my-app/
  .gitignore
  Cargo.toml
  application.yaml
  AGENTS.md          # agent-facing guidance (idiomatic R2E patterns)
  CLAUDE.md          # imports AGENTS.md
  src/
    app.rs
    env.rs
    lib.rs
    main.rs
    controllers/
      mod.rs
      hello.rs
  tests/
    app.rs           # boots the same App via #[r2e::test]

With --db sqlite, you also get a migrations/ directory and a SqlitePool producer registered in app.rs. With --auth, the builder registers an Arc<JwtClaimsValidator> producer. With --openapi, the builder includes OpenApiPlugin and your API docs are served at /docs. With --grpc, you get a proto/greeter.proto sample, a build.rs, and GrpcServer plugin in the builder.

Generated main.rs

The generated entry point contains one line:

#![allow(unused)]
fn main() {
r2e::app_main!(MyApp);
}

app_main! includes canonical src/app.rs in the binary, generates the Tokio entry point, and selects normal serving or hot reload. src/lib.rs includes the same source for integration tests. All selected plugins, producers, beans, and controllers are assembled once in App::build inside app.rs.

Generated application.yaml

app:
  name: "my-app"

# Read by serve_auto()
server:
  port: 3000

With --db sqlite:

database:
  url: "sqlite:data.db?mode=rwc"

With --auth:

security:
  jwt:
    issuer: "my-app"
    audience: "my-app"
    jwks-url: "${JWKS_URL}"

With --grpc:

grpc:
  port: 50051

Code generation

Controllers

r2e generate controller UserController

Generates src/controllers/user_controller.rs with a skeleton controller:

#![allow(unused)]
fn main() {
#[controller]
pub struct UserController {
    // #[inject]
    // your_service: YourService,
}

#[routes]
impl UserController {
    #[get("/your-path")]
    async fn list(&self) -> Json<String> {
        Json("Hello from UserController".into())
    }
}
}

Updates src/controllers/mod.rs with pub mod user_controller;.

Services

r2e generate service UserService

Generates src/user_service.rs with a skeleton service struct:

#![allow(unused)]
fn main() {
#[derive(Clone)]
pub struct UserService {
    // Add your dependencies here
}

impl UserService {
    pub fn new() -> Self {
        Self {}
    }
}
}

CRUD scaffolding

r2e generate crud Article --fields "title:String body:String published:bool"

Generates a complete CRUD set — 5 files in one command:

FileWhat it contains
src/models/article.rsArticle entity + CreateArticleRequest / UpdateArticleRequest
src/services/article_service.rsService with #[bean], list/get/create/update/delete methods
src/controllers/article_controller.rsREST controller at /articles with GET, POST, PUT, DELETE
migrations/<timestamp>_create_articles.sqlSQL migration (only if migrations/ directory exists)
tests/article_test.rsIntegration test skeleton

Field format: name:Type pairs. Supported types:

Rust TypeSQL ColumnExample
StringTEXT NOT NULLtitle:String
i64INTEGER NOT NULLage:i64
f64REAL NOT NULLprice:f64
boolBOOLEAN NOT NULLactive:bool
Option<String>TEXT (nullable)bio:Option<String>
Option<i64>INTEGER (nullable)parent_id:Option<i64>

An id INTEGER PRIMARY KEY AUTOINCREMENT column is always generated automatically.

After generation, you need to:

  1. Register the controller in src/app.rs: .register_controller::<ArticleController>()
  2. Register the service in App::build: .register::<ArticleService>() (before build_state())
  3. Run the SQL migration
  4. Run cargo check

Middleware (interceptors)

r2e generate middleware AuditLog

Generates src/middleware/audit_log.rs with a self-contained Interceptor<R> implementation (the SelfBuilt opt-in makes it usable in #[intercept(...)]):

#![allow(unused)]
fn main() {
pub struct AuditLog;

impl SelfBuilt for AuditLog {}

impl<R: Send> Interceptor<R> for AuditLog {
    fn around<F, Fut>(&self, ctx: InterceptorContext, next: F) -> impl Future<Output = R> + Send
    where
        F: FnOnce() -> Fut + Send,
        Fut: Future<Output = R> + Send,
    {
        let method_name = ctx.method_name;
        async move {
            tracing::info!(method = method_name, "AuditLog: before");
            let result = next().await;
            tracing::info!(method = method_name, "AuditLog: after");
            result
        }
    }
}
}

Use it on controller methods with #[intercept(AuditLog)].

gRPC services

r2e generate grpc-service User --package myapp

Generates two files:

proto/user.proto — service definition with GetUser and ListUser RPCs:

syntax = "proto3";

package myapp;

service User {
  rpc GetUser (GetUserRequest) returns (GetUserResponse);
  rpc ListUser (ListUserRequest) returns (ListUserResponse);
}

src/grpc/user.rs — Rust implementation with #[grpc_routes]:

#![allow(unused)]
fn main() {
use r2e::prelude::*;

use super::proto;
use proto::myapp::*;

#[controller]
pub struct UserService {
    // #[inject]
    // your_dependency: YourDependency,
}

#[grpc_routes(proto::myapp::user_server::User, descriptor = proto::FILE_DESCRIPTOR_SET)]
impl UserService {
    async fn get_user(&self, request: tonic::Request<GetUserRequest>) -> Result<tonic::Response<GetUserResponse>, tonic::Status> {
        // ...
    }

    async fn list_user(&self, _request: tonic::Request<ListUserRequest>) -> Result<tonic::Response<ListUserResponse>, tonic::Status> {
        // ...
    }
}
}

The command also creates src/grpc/mod.rs (with the shared proto module) if it doesn’t exist and appends pub mod user; to it.

After generation:

  1. Register in src/app.rs, inside App::build: .register_grpc_service::<UserService>()
  2. cargo build — the build.rs helper (r2e_grpc_build::compile()) picks up the new .proto automatically. If there is no build.rs yet, run r2e add grpc first.

Development server

r2e dev

Supervises dx serve --hot-patch with the dev-reload feature enabled. Normal application edits are patched in place; changes to src/env.rs, src/env/**, Cargo.toml, or build.rs trigger a safe full restart.

Use --open to auto-open the browser:

r2e dev --open

Requires the Dioxus CLI: cargo install dioxus-cli.

Test runner and coverage

r2e test
r2e test --coverage
r2e test --sonarqube

r2e test runs cargo test. Use --coverage to run cargo llvm-cov, or --sonarqube to generate an LCOV report at coverage/lcov.info.

Configure SonarQube with:

sonar.rust.lcov.reportPaths=coverage/lcov.info

Useful options:

r2e test --workspace
r2e test -p my-crate --features sqlite openapi
r2e test --sonarqube --output-path reports/lcov.info
r2e test -- --nocapture

Coverage requires:

cargo install cargo-llvm-cov
rustup component add llvm-tools-preview

r2e test generates the report only; CI should run sonar-scanner afterwards when SonarQube analysis is needed.

Extension management

r2e add security    # adds r2e-security to Cargo.toml
r2e add data-sqlx   # adds the managed SQLx transaction backend
r2e add openapi     # adds r2e-openapi
r2e add events      # adds r2e-events
r2e add scheduler   # adds r2e-scheduler
r2e add cache       # adds r2e-cache
r2e add rate-limit  # adds r2e-rate-limit
r2e add utils       # adds r2e-utils (Logged, Timed, Cache interceptors)
r2e add grpc        # adds r2e-grpc
r2e add test        # adds r2e-test (TestApp, TestJwt)

If the dependency is already present, prints a warning without duplicating it.
